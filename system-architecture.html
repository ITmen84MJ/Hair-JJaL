B. 데이터 스토어 시스템 (useDataStore)

CRUD 추상화 레이어 — 컴포넌트는 구현체를 모름

함수파라미터반환값동작
addClientOmit<Client, 'id'|'createdAt'>Promise<Client>UUID 생성 후 저장. 성공 토스트
updateClientid, Partial<Client>Promise<void>부분 업데이트
deleteClientidPromise<void>고객 + 연관 상담/예약 일괄 삭제
addConsultationOmit<Consultation, 'id'|'shareToken'|'createdAt'>Promise<Consultation>shareToken 자동 생성
updateConsultationid, Partial<Consultation>Promise<void>modificationRequest·isShared 변경은 silent
deleteConsultationidPromise<void>단건 삭제
toggleShareidPromise<void>isShared 토글 → 공유링크 ON/OFF
addDesignerOmit<Designer, 'id'>Promise<Designer>지점에 디자이너 등록
updateDesignerid, Partial<Designer>Promise<void>이름 변경 시 consultations.stylistName 동기화
addBookingOmit<Booking, 'id'|'createdAt'>Promise<Booking>예약 신청
updateBookingid, Partial<Booking>Promise<void>확정·취소 상태 변경
addShopOmit<Shop, 'id'|'createdAt'>Promise<Shop>원장 가입 시 지점 생성
updateShopid, Partial<Shop>Promise<void>지점 정보 수정
LocalStore 특이사항
  • 300ms 디바운스 자동 저장
  • 데이터 버전 4 (구버전 자동 삭제)
  • Mock 데이터 초기값 (demo 계정)
  • 80% 저장 공간 도달 시 경고 토스트
SupabaseStore 특이사항
  • 마운트 시 전체 데이터 병렬 로드
  • Optimistic Update (로컬 상태 즉시 반영)
  • Realtime 구독 4개 테이블 (B4 통합)
  • isLoading 상태 제공

C. 실시간 동기화 시스템 (B4 — Supabase Realtime)

같은 지점 디자이너 간 데이터 자동 동기화

항목내용
구현 위치useSupabaseStore.ts 내부 useEffect — 별도 훅 불필요
채널명hairjjal_store
구독 테이블clients · consultations · designers · bookings (4개)
이벤트INSERT · UPDATE · DELETE 모두 (event: '*')
동작 방식이벤트 수신 → 해당 테이블 전체 재조회 → setState() 갱신
충돌 해결서버 데이터가 Source of Truth. 마지막 저장이 우선
RLS 연동같은 지점(shop_id) 변경만 수신 — DB 레벨 필터링
정리컴포넌트 언마운트 시 supabase.removeChannel() 자동 호출

F. 데이터 이전 시스템 (dataMigration)
